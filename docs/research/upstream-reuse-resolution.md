## Resolution

The [Upstream reuse audit](https://github.com/dvcol/devkit-extension/issues/2) supports selective reuse through local provider adapters. Exact published artifacts and their integrity records are the operational baseline. The audit records viable contracts and explicit gaps; it does not claim the portable SDK, browser adapters or conformance suite already exist.

### Consumable baseline

Checked on 2026-09-22:

- `devframe`, `@devframes/hub`, `@devframes/json-render`, `@devframes/json-render-ui`, `@devframes/vite`: **1.0.0**.
- `@vitejs/devtools` and `@vitejs/devtools-kit`: **0.7.5**.
- `@dvcol/cdb`, `@dvcol/cdb-extension`, `@dvcol/cdb-devframe`, `@dvcol/cdb-birpc`, `@dvcol/cdb-websocket`, `@dvcol/cdb-broker`: **0.3.0**.

All thirteen downloaded baseline tarballs matched their npm registry SHA-512 integrity values; all 150 declared export targets existed. The Devframe package family has exact 1.0.0 peer relationships, and CDB's Devframe adapter pins that family at 1.0.0. The Vite adapter accepts Vite 7 or 8. These are package constraints, not proof of every permitted combination. [Devframe](https://registry.npmjs.org/devframe/1.0.0), [hub](https://registry.npmjs.org/@devframes%2fhub/1.0.0), [Vite adapter](https://registry.npmjs.org/@devframes%2fvite/1.0.0), [DevTools](https://registry.npmjs.org/@vitejs%2fdevtools/0.7.5), [kit](https://registry.npmjs.org/@vitejs%2fdevtools-kit/0.7.5), [CDB Devframe adapter](https://registry.npmjs.org/@dvcol%2fcdb-devframe/0.3.0).

The checked source baselines were Devframe `a3f967755af99a0a0d8dd82b7b5d4f3dd4aec0bc`, DevTools `121656dfc5866b2f8de5baa8e0b6166ec28599c8` and local CDB `89bdf211e8e21d86aba70051c366bb03b38d43d8`. Selected files were compared with upstream main at Devframe `18fa60effeb928eb445add2a536cd44906a59981`, DevTools `ad2d6df720a513670f93ac09318ae6dc8b4a0623` and CDB `4053273d6d15ddb17abc3e1b14fc8d58122cb49a`. Registry records supplied no `gitHead`; complete byte equivalence to those source revisions is **not proved or assumed**. Pinned published artifacts, their exports and observed behavior are sufficient for this audit's baseline. A reproducible upstream build would answer a stronger provenance question and is not required here.

### Adoption matrix

| Capability                        | Resolution and public entry                                                                                                                                                                                                                                                                                                                             |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| RPC                               | Reuse `devframe/rpc/client` with a local browser Port adapter. `createRpcClient` accepts channel callbacks and exposes explicit call/close methods. High-level `devframe/client` only models WebSocket, SSE and static transports.                                                                                                                      |
| State                             | Reuse `devframe/utils/shared-state` for in-memory mutation, patching and subscriptions. Adapt server publication; define persistence, conflict, generation and recovery policy locally.                                                                                                                                                                 |
| Host services, commands and docks | Reuse `devframe/node`, `@devframes/hub/node`, `/types` and `/client` within their respective host boundaries. Do not expose Node contexts, filesystem or terminal facilities as universal extension APIs.                                                                                                                                               |
| JSON authoring                    | Reuse the serializable model and refs from `@devframes/json-render` and `/hub`. Adapt `/node` view publication because its public argument is a Node context.                                                                                                                                                                                           |
| Renderer                          | Conditionally reuse the self-contained browser asset returned by the public Node helper `jsonRenderUiRenderer()` from `@devframes/json-render-ui/hub`. There is no public browser factory export. The [Renderer and surface contract](https://github.com/dvcol/devkit-extension/issues/12) owns host typing before an extension adapter can be claimed. |
| Page bridge                       | Reuse/adapt `devframe/in-page-channel`; extension isolated/main-world integration and trust remain separate work.                                                                                                                                                                                                                                       |
| Server integration                | Adapt through `@devframes/vite/hub` and `@vitejs/devtools-kit/node`, including `createPluginFromDevframe`. Vite raw context is optional and local; Devframe, hub and kit contexts are layered.                                                                                                                                                          |
| Transforms and reload             | Reuse existing injection/asset-serving pieces. Define portable HTTP/HTML transform capabilities and watched production live-preview orchestration separately. | Extension runtime                 | Build local execution, permission, discovery, routing, recovery and surface adapters. No inspected upstream package supplies this complete backend.                                                                                                                                                                                                     |

These classifications follow the public [RPC channel](https://github.com/devframes/devframe/blob/18fa60effeb928eb445add2a536cd44906a59981/packages/devframe/src/rpc/client.ts), [state implementation](https://github.com/devframes/devframe/blob/18fa60effeb928eb445add2a536cd44906a59981/packages/devframe/src/utils/shared-state.ts), [kit context](https://github.com/vitejs/devtools/blob/ad2d6df720a513670f93ac09318ae6dc8b4a0623/packages/kit/src/node/context.ts), [renderer export map](https://registry.npmjs.org/@devframes%2fjson-render-ui/1.0.0), [CDB exports](https://registry.npmjs.org/@dvcol%2fcdb/0.3.0) and [extension exports](https://registry.npmjs.org/@dvcol%2fcdb-extension/0.3.0). If a required release or adapter seam is unavailable, keep that capability explicitly unavailable or implement a narrow local alternative. Do not silently adopt unpublished source or private deep imports.

### Observed evidence and limits

With Node 26.9.0, pnpm 12.5.1 and Rolldown 1.2.6, sixteen relevant released browser entry points bundled with tree shaking disabled and no Node builtins or external imports. The returned renderer asset also bundled. As expected, the renderer's Node helper, `devframe/node` and the CDB Devframe package root failed the browser-builtin guard.

A real Node MessageChannel probe confirmed that explicit RPC close rejects an outstanding call and removes listeners. Released shared-state instances passed patch synchronization, deduplication and unsubscribe checks. An empty embedded CDB bridge listed no targets and rejected use after disposal. These tests do not prove browser Port disconnect detection, worker recovery, rendering under extension CSP or actual CDP execution.

The renderer's current public type requires `DevframeClientContext`; its RPC type restricts transport to `websocket | sse | static`. Runtime use is narrower, but a cast or fabricated transport value would not prove a valid Port-backed contract. The [Renderer and surface contract](https://github.com/dvcol/devkit-extension/issues/12) must choose a narrower supported interface, wrapper or upstream extension point. [Mount contract](https://github.com/devframes/devframe/blob/18fa60effeb928eb445add2a536cd44906a59981/packages/hub/src/client/renderers.ts), [RPC type](https://github.com/devframes/devframe/blob/18fa60effeb928eb445add2a536cd44906a59981/packages/devframe/src/client/rpc.ts).

CDB reserves `Fetch.enable` and `Fetch.disable`; the publisher's subscription activation sends domain enable/disable without configuration parameters. This is an explicit gap for configured patterns or response-stage interception. It is not evidence that all Fetch functionality is impossible. The [Debugger and CDB contract](https://github.com/dvcol/devkit-extension/issues/10) and [Injection and transform contract](https://github.com/dvcol/devkit-extension/issues/11) must settle a supported mechanism and one lifecycle owner. [Catalogue](https://github.com/dvcol/chrome-debugger-bridge/blob/4053273d6d15ddb17abc3e1b14fc8d58122cb49a/packages/core/src/cdp-catalogue.generated.ts), [publisher](https://github.com/dvcol/chrome-debugger-bridge/blob/4053273d6d15ddb17abc3e1b14fc8d58122cb49a/packages/extension/src/selected-tab-publisher.ts).

### Remaining decisions and acceptance

- [Contribution and realm contract #5](https://github.com/dvcol/devkit-extension/issues/5): separate provider identity, execution context, UI surface and layered local raw primitives; settle the minimal portable action/state/view/lifecycle contract.
- [Server adapter contract #6](https://github.com/dvcol/devkit-extension/issues/6): fix released host factories, authentication and disposal; exercise the shared contribution in standalone Devframe and DevTools.
- [State scope and recovery #8](https://github.com/dvcol/devkit-extension/issues/8), informed by [Browser capability audit #3](https://github.com/dvcol/devkit-extension/issues/3): real Port interruption must settle pending calls and remove subscriptions; reconnect must avoid stale or duplicate updates. Define persistence and worker recovery separately.
- [Debugger and CDB contract #10](https://github.com/dvcol/devkit-extension/issues/10): prove actual embedded Chrome command/event, lease, generation, native coexistence and disposal; prove existing-Devframe-peer composition without taking ownership of its transport.
- [Injection and transform contract #11](https://github.com/dvcol/devkit-extension/issues/11): resolve configured Fetch interception and paused-request cleanup, or record explicit unavailable behavior without bypassing CDB ownership.
- [Renderer and surface contract #12](https://github.com/dvcol/devkit-extension/issues/12): settle the type gap, then run the same spec with state/action/error/disposal behavior in real web and Chromium/Firefox extension pages; cover every supported surface in its final contract.
- [Live preview and reload contract #13](https://github.com/dvcol/devkit-extension/issues/13): observe watched renderer bytes and mounted-module replacement with a live production backend, accounting for module caches and layer-specific recovery.
- [Examples and API coverage contract #14](https://github.com/dvcol/devkit-extension/issues/14): map every public SDK API/hook/feature to runnable examples and real-host success or unsupported assertions, plus failure/lifecycle cases. Include every package, both server hosts, both browsers and all contribution combinations. Compile-only samples and browser mocks are supplemental evidence.
- [Release and conformance contract #16](https://github.com/dvcol/devkit-extension/issues/16): enforce complete coverage, exact artifact integrity and compatible peer versions when adopting or upgrading packages; track any source-only patches explicitly.

Full Node contexts as the portable API, private renderer imports, assumed browser execution from successful bundling, and automatic equivalence between static builds and live preview are rejected approaches. Framework-neutral authoring remains compatible with a Vue-based reference renderer. The Devframe/DevTools/CDB manifests declare MIT; upstream JSON-render core/Vue declare Apache-2.0. Preserve notices and the wrapper's `@json-render/core ^0.20.0` compatibility range rather than independently moving it to 0.21.0. [Wrapper metadata](https://registry.npmjs.org/@devframes%2fjson-render/1.0.0), [upstream core metadata](https://registry.npmjs.org/@json-render%2fcore/0.21.0).

The audit's substantive Definition of Done is met through observed evidence and these named follow-ups. They own the remaining integration evidence and implementation decisions. Audit completion does not claim that those later obligations have passed, and does not create reverse dependencies on descendant tickets.
