### Why the contribution lifecycle still exists

The inspected native `DevframeServicesHost` supports local `provide/get/has/whenAvailable` and package-based wire-service installation. Its semantics are useful, but differ from the already accepted SDK contract:

| Behavior                   | Native service API at the reviewed baseline                                                                                                        | Accepted contribution contract                                                                          |
| -------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| Identity and compatibility | Wire services use npm package identity and semver strings/ranges.                                                                                  | Imported capability ID plus an exact positive integer contract version, independent of package version. |
| Repeated installation      | Wire-service options are collected/merged; an installed package is reused across contexts sharing an RPC host. Plain `provide` rejects duplicates. | Duplicate definitions reject admission, with the explicitly configured relaxed skip behavior.           |
| Dependency observation     | `whenAvailable` observes provision; revocation removes the value without a matching dependency-loss event.                                         | Loss invalidates dependents and ends their owned activation before replacement.                         |
| Replacement                | Package installation/ready barrier is not the SDK's contribution teardown/replace protocol.                                                        | Await asynchronous cleanup; failed cleanup blocks a successor; failed setup requires explicit retry.    |

Evidence: [native service types](https://github.com/devframes/devframe/blob/a3f967755af99a0a0d8dd82b7b5d4f3dd4aec0bc/packages/devframe/src/types/services.ts) and [implementation](https://github.com/devframes/devframe/blob/a3f967755af99a0a0d8dd82b7b5d4f3dd4aec0bc/packages/devframe/src/node/host-services.ts). Do not substitute one API for the other by casting or translating a numeric contract version to npm semver. If upstream supplies equivalent ownership semantics, replace the local mechanism while retaining its behavioral tests. Native services remain directly available through the actual native context.

## Upgrade and evidence boundary

The [original reuse audit](./upstream-reuse-resolution.md) records pinned published artifacts, exact inspected source revisions and observed limits. Source inspection is not proof that every checkout feature matches the published tarball. `pnpm-lock.yaml` and [the patch inventory](../../patches/README.md) define the working dependency baseline.

For an adapter change or dependency upgrade, name the public export used, demonstrate the missing behavior, and run the affected type, runtime and packed-consumer checks. Delete a patch when the unpatched release passes its existing checks. A root pnpm patch does not automatically reach a published package's consumers. Devframe isolation remains an explicit backport; Vite remains unpatched. No new upstream PR is part of this review.

Concrete technical investigations remain: native RPC registration cleanup, public disconnect/cancellation ownership, a real authenticated remote fixture, actual extension Ports and renderer host typing. Reuse must be demonstrated at those seams; private fields, fabricated transports and a successful mock do not establish compatibility.

## Native browser integration prototype, 2026-09-28

The owner chose to expose the missing native integration points instead of adopting the in-page channel's reduced shared-state interface. [Two review commits](../probes/native-port/README.md#review-commits), based on upstream v1.1.0, expose native shared-state factories, a browser renderer import and JSON view publication with structural native dependencies. Per-connection birpc metadata supplies subscription identity. Existing node paths and default renderer context types remain compatible.

The prototype also corrects initial state-fetch rejection propagation and cleans up a partially mounted reference renderer. A focused regression first reproduced the waiting promise and passes with the rejection forwarded. The real Chromium proof validates both accepted and denied admission, native actions/writes, serialization, per-peer disconnect and reconnect without replay. After review, scoped upstream lint, Knip, type checks, 44 focused tests, 110 API snapshot checks and browser artifact checks pass. The proof's TypeScript 7/Oxlint checks pass too, and its Chromium rerun reports zero page errors.

The owner approved [Devframe draft PR #410](https://github.com/devframes/devframe/pull/410), which is open for review. Review fixes retain the existing diagnostic export, cover native Node subscriptions, declare the renderer peer dependency and document reuse of one publishing context. The working SDK baseline remains v1.0.0 and its existing patches. A compatible downstream backport and the portable WebExtension provider remain subsequent work. The prototype does not justify importing Node or a full hub context into a worker.
