# Explicit native RPC exposure

Research for [Server adapter contract](https://github.com/dvcol/devkit-extension/issues/6), checked on 2026-09-27. The owner selected host-owned methods and one provider startup object containing `services`, `plugins` and `expose`. This note covers the smallest implementation using the installed public Devframe API; it does not define remote discovery or a second transport.

## Recommendation

Build one native RPC definition per explicitly exposed action and capability operation, using `context.rpc.register`. Keep those definitions for the native host lifetime. Their handlers capture the current provider at dispatch and delegate to its existing invocation/binding API. Preserve the native host's authentication, serialization and schema validation. Provider disposal changes availability, not the RPC registry. The finite exposure configuration must remain fixed when replacing the provider on the same host.

The initial implementation can support targetless unary calls without an upstream patch. Required-target calls need a real target authority; ordinary client cancellation does not currently reach the backend through the installed hub API. Reject unsupported combinations explicitly and keep these omissions visible in the contract and coverage table. They do not justify a replacement authentication or RPC system.

## Definition and schema mapping

The public `RpcFunctionDefinition` accepts `args: readonly StandardSchemaV1[]` and `returns: StandardSchemaV1`. Both native argument and result inference use `StandardSchemaV1.InferInput`, matching the SDK's accepted guard-only semantics. Native validation awaits asynchronous schemas and returns the original values; it does not apply a schema transform or remove extra object fields. [Definition types](https://github.com/devframes/devframe/blob/a3f967755af99a0a0d8dd82b7b5d4f3dd4aec0bc/packages/devframe/src/rpc/types.ts), [inference](https://github.com/devframes/devframe/blob/a3f967755af99a0a0d8dd82b7b5d4f3dd4aec0bc/packages/devframe/src/rpc/utils.ts), [validation](https://github.com/devframes/devframe/blob/a3f967755af99a0a0d8dd82b7b5d4f3dd4aec0bc/packages/devframe/src/rpc/validate-io.ts).

| Portable element              | Native declaration                                           | Handler delegates to                                                                  |
| ----------------------------- | ------------------------------------------------------------ | ------------------------------------------------------------------------------------- |
| Action descriptor             | One named method with the action's input/output schemas      | `selected.invoke({ action, input })`                                                  |
| Capability operation          | One named method per operation with its input/output schemas | Resolve the selected provider's capability, then invoke that operation on the binding |
| Expected provider incarnation | A separately validated argument alongside the business input | Compare against the captured provider before invoking                                 |

Keep literal schema tuples, such as `args: [incarnationSchema, operation.input] as const`, when using `createDefineWrapperWithContext`; a widened schema array cannot retain positional type inference. Returning the operation's actual result allows `returns: operation.output` directly. No universal `{ success, value }` wrapper is needed. [Public definition helper](https://github.com/devframes/devframe/blob/a3f967755af99a0a0d8dd82b7b5d4f3dd4aec0bc/packages/devframe/src/rpc/define.ts).

The SDK operation contract does not distinguish read-only from mutating capability methods. Do not infer read-only safety from the word “capability.” Native `type: 'action'` supports ordinary results in its actual type and runtime; avoiding `static`, dumps, snapshots and opt-in result caching prevents accidental caching of effects. Omit `agent` unless agent exposure is separately configured; omit `jsonSerializable` to retain native structured-clone transport for business values. [Function and agent options](https://github.com/devframes/devframe/blob/a3f967755af99a0a0d8dd82b7b5d4f3dd4aec0bc/packages/devframe/src/rpc/types.ts), [agent registration rules](https://github.com/devframes/devframe/blob/a3f967755af99a0a0d8dd82b7b5d4f3dd4aec0bc/packages/devframe/src/rpc/agent-json-serialization.ts).

Do not call `validateRpcArgs` or `validateRpcReturn` directly: they are exported but marked `@internal`. Native definitions already invoke them. The existing provider guard remains necessary for local calls; sharing schemas does not require bypassing its owned invocation path. [Native handler](https://github.com/devframes/devframe/blob/a3f967755af99a0a0d8dd82b7b5d4f3dd4aec0bc/packages/devframe/src/rpc/handler.ts), [SDK invocation](../../packages/runtime/src/invocation.ts).

## Names, collision checks and registration failure

Native method identity is its string name. An adapter-generated name needs the contract kind, descriptor ID, exact numeric version and capability operation name; include the provider ID if the chosen host namespace supports more than one configured provider identity. Portable IDs are strings and may themselves contain separators, so naïvely concatenating IDs and operation names is not collision-safe. Use one deterministic collision-free encoding and test separator-containing IDs. The encoding is adapter-owned naming, not a new RPC protocol. [Collector](https://github.com/devframes/devframe/blob/a3f967755af99a0a0d8dd82b7b5d4f3dd4aec0bc/packages/devframe/src/rpc/collector.ts), [portable descriptors](../../packages/core/src/types.ts).

`context.scope(namespace).rpc.register` is public, but rejects a supplied bare method name containing `:`. It therefore does not directly solve encoding arbitrary portable IDs. Registering a complete qualified name on the base `context.rpc` is supported. [Scoped registration](https://github.com/devframes/devframe/blob/a3f967755af99a0a0d8dd82b7b5d4f3dd4aec0bc/packages/devframe/src/node/scope.ts), [qualification rule](https://github.com/devframes/devframe/blob/a3f967755af99a0a0d8dd82b7b5d4f3dd4aec0bc/packages/devframe/src/utils/scope.ts).

Preflight the entire exposure list before mutating the native registry: reject duplicate descriptor identities and generated names, validate target support, then use public `context.rpc.has(name)`/`get(name)` to detect conflicts with foreign native registrations. Never use `force` to silently replace another integration's method. A successor may reuse only methods already owned by this host exposure, with its original finite contracts; it must not register a growing history of names. [Collector inspection and registration methods](https://github.com/devframes/devframe/blob/a3f967755af99a0a0d8dd82b7b5d4f3dd4aec0bc/packages/devframe/src/rpc/collector.ts).

Native registration is not transactional: it stores a definition before synchronously notifying `onChanged` listeners. A throwing listener propagates an error while leaving the method registered. There is no public batch rollback or unregister-and-notify API. Preflight prevents ordinary collisions but cannot guarantee rollback after arbitrary observer failures. Register against an unavailable provider slot and publish the provider only after startup succeeds. On registration failure, leave retained owned methods unavailable, fail startup and report the cause; do not claim native registrations were removed. A host can be restarted if those definitions must disappear. [Registration order](https://github.com/devframes/devframe/blob/a3f967755af99a0a0d8dd82b7b5d4f3dd4aec0bc/packages/devframe/src/rpc/collector.ts), [earlier lifecycle investigation](./native-rpc-lifecycle.md).

## Replacement and current session

A method handler should synchronously capture the current provider, check the expected incarnation and then delegate without reading the slot again. Clear availability before old-provider disposal and expose a successor only after cleanup succeeds. An in-flight call retains its selected provider. Existing provider activation ownership supplies contribution cancellation and cleanup barriers; the native method does not invent another lifetime controller. [Accepted architecture](../../ARCHITECTURE.md#host-owned-native-rpc-methods), [provider invocation ownership](../../packages/runtime/src/provider-bindings.ts).

Native `setup(context)` is cached per definition object and context. It is not a request hook, has no cleanup return, and must not capture caller identity or a provider incarnation that will change. A direct handler closing over the actual context and current-provider slot needs no native setup function. [Setup cache](https://github.com/devframes/devframe/blob/a3f967755af99a0a0d8dd82b7b5d4f3dd4aec0bc/packages/devframe/src/rpc/handler.ts).

Read `context.rpc.getCurrentRpcSession()` inside the actual handler when session information is needed. The native server establishes that session with `AsyncLocalStorage` around each remote call. Authentication uses the named method and current session before executing the handler. Do not replace that gate with a mandatory SDK callback or an unconditional `meta.isTrusted` check: a host may legitimately supply a different native auth handler. Local `invokeLocal` bypasses transport authorization; before a host binds its RPC server, `getCurrentRpcSession()` can throw rather than simply returning `undefined`. [Native gate](https://github.com/devframes/devframe/blob/a3f967755af99a0a0d8dd82b7b5d4f3dd4aec0bc/packages/devframe/src/node/rpc-core.ts), [session/local invocation implementation](https://github.com/devframes/devframe/blob/a3f967755af99a0a0d8dd82b7b5d4f3dd4aec0bc/packages/devframe/src/node/host-functions.ts).

## Explicit unsupported boundaries

| Boundary                                                   | Current evidence                                                                                                                                                       | Required behavior for this slice                                                                                                               |
| ---------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| Target-required remote operation                           | The portable runtime checks presence, not the sender's authority or target generation. No server target resolver is supplied by `createDevframeProvider({ context })`. | Reject exposure requiring target resolution until a real host integration provides that authority. A wire object's shape is not authorization. |
| Client abort/disconnect cancelling a unary backend handler | Native unary signatures and sessions have no abort signal. Installed hub startup does not forward standalone Devframe peer lifecycle hooks.                            | Preserve client rejection and no replay. Do not claim backend cancellation or serialize an `AbortSignal`.                                      |
| Disposal removing native method names                      | Public collector lacks unregister-and-notify.                                                                                                                          | Keep finite host-owned declarations, and reject unavailable implementations. This matches the selected lifetime.                               |
| Atomic registration rollback                               | Observer exceptions occur after insertion.                                                                                                                             | Keep failed startup unavailable and report retained declarations; do not use private mutation as cleanup proof.                                |
| Remote catalog synchronization                             | Native method enumeration is not portable provider/contribution availability.                                                                                          | Keep a live remote catalog as separate adapter work; registered methods alone cannot establish availability.                                   |

Sources: [local target assertions](../../packages/runtime/src/invocation.ts), [native session/streaming distinction](https://github.com/devframes/devframe/blob/a3f967755af99a0a0d8dd82b7b5d4f3dd4aec0bc/packages/devframe/src/types/rpc.ts), [hub entry point](https://github.com/devframes/devframe/blob/a3f967755af99a0a0d8dd82b7b5d4f3dd4aec0bc/packages/hub/src/node/initiate.ts), [collector](https://github.com/devframes/devframe/blob/a3f967755af99a0a0d8dd82b7b5d4f3dd4aec0bc/packages/devframe/src/rpc/collector.ts), [local portable catalog](../../packages/core/src/catalog.ts).

## Focused implementation checks

The affected package should prove direct schema reuse, malformed/stale incarnation rejection, non-exposed method absence, native-name collision before provider publication, service/action availability after disable/dispose, rejection through an old incarnation after replacement, and no rerouting of an already-started invocation. Keep authenticated real-socket checks for both Devframe and DevTools hosts. Add a throwing native registry observer case so startup failure cannot accidentally publish a working provider behind partially registered exposure. Required-target and unary cancellation limitations must remain explicit instead of receiving synthetic successful coverage.
